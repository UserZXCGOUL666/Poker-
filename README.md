# Poker Club — Telegram Mini App

Готовый MVP спортивного покерного клуба: мобильное Telegram Mini App, защищённая админка, API, PostgreSQL и Telegram-бот.

## Что уже работает

- авторизация через подписанный `Telegram.WebApp.initData`;
- ограниченный вход из обычного браузера по одноразовым приглашениям;
- доступ в админку только для ID из `ADMIN_TELEGRAM_IDS`;
- главная страница, ближайшая игра, результаты недели и лидеры;
- календарь турниров, сезонный и недельный рейтинг, профиль игрока;
- самостоятельная регистрация на турнир, лист ожидания и автоматический перевод на освободившееся место;
- автоматическая рассадка по столам с настраиваемой вместимостью, ручными перестановками и публикацией мест игрокам;
- создание сезонов и турниров;
- редактирование турниров, статусов и сезонов из единого рабочего пространства;
- ввод результатов расстановкой игроков по местам;
- ручное начисление и списание очков конкретному игроку;
- атомарное пакетное начисление очков по итогам турнира и безопасная отмена ошибочной проводки;
- Telegram-уведомления об очках и изменениях регистрации;
- персональные Telegram-уведомления с номером стола и места после публикации рассадки;
- добровольная передача телефона через нативное подтверждение Telegram;
- еженедельные шаблоны турниров с автоматическим заполнением расписания;
- приватные заметки, теги и расширенные фильтры игроков;
- отдельный аудит всех значимых действий администратора;
- смена фонового изображения рейтинговой карточки из настроек без нового деплоя;
- финализация сезона с неизменяемым снимком итогового рейтинга;
- журнал операций: причина, администратор, сезон и баланс после изменения;
- Telegram-бот с командами `/start`, `/app` и `/phone`;
- рассылка напоминания о турнире всем пользователям, запускавшим бота;
- адаптивный интерфейс админки для телефона и компьютера;
- операционный экран **Сегодня**, который ведёт администратора от заявок до начисления очков;
- быстрый персональный чек-ин, режим выбывания и локально сохраняемый черновик результатов;
- компактное меню администратора с карточкой игрока и быстрыми действиями;
- Blueprint для Render и конфигурация SPA для Vercel.

## Ограниченный доступ из браузера

Обычное открытие Vercel URL без Telegram по-прежнему не авторизует пользователя. Доступ выдаётся адресно из админки:

1. Пользователь хотя бы один раз открывает Mini App через Telegram, чтобы появиться в БД.
2. Администратор открывает раздел **Доступ**, выбирает пользователя и создаёт приглашение.
3. Ссылка действует 30 минут, принимается только один раз и должна передаваться лично.
4. После первого открытия браузер получает персональную сессию на 30 дней.
5. Администратор видит активную сессию и может немедленно отозвать её в том же разделе.

В PostgreSQL сохраняется только SHA-256-хеш одноразового токена. Сам токен показывается администратору один раз. Каждая браузерная сессия имеет отдельный идентификатор, срок действия и отметку отзыва; API проверяет её на каждом защищённом запросе. Отзыв не влияет на обычный Telegram-вход пользователя.

## Учёт очков

Очки не рассчитываются автоматически по занятому месту. Их можно начислить одному игроку в разделе **Игроки** или сразу всем после проверки результатов в **Турниры → Результаты**.

Для надёжности используются две связанные сущности:

- `User.points` — текущий баланс активного сезона для быстрого рейтинга;
- `PointTransaction` — журнал каждого начисления, списания и встречной проводки с итоговым балансом;
- `PointBatch` — атомарная группа операций по конкретному турниру.

Изменение выполняется в serializable-транзакции PostgreSQL: обновление баланса и запись журнала либо сохраняются вместе, либо полностью отменяются. Отрицательный баланс запрещён, повторная отправка той же операции защищена idempotency-ключом.

Пакет турнира выполняется целиком в serializable-транзакции и может быть создан только один раз. Если администратор ошибся, исходная запись не удаляется: сервер создаёт равную по модулю встречную проводку. При завершении сезона рейтинг сохраняется в `SeasonStanding`, после чего операции этого сезона изменить нельзя.

## Регистрация и лист ожидания

Игрок нажимает **Участвовать** в карточке предстоящей игры. Пока есть места, заявка попадает в основной список. После заполнения вместимости новые заявки помещаются в очередь и показывают игроку его позицию. Если участник отменяет запись, первый человек из очереди автоматически получает место и сообщение в Telegram.

Администратор во вкладке **Участники** может добавить игрока вручную, подтвердить приход, отметить участие, перевести в очередь или отменить заявку. Обычный пользователь может сам отменить только заявку на ещё не начавшуюся игру.

## Пятиминутный сценарий администратора

Админка по умолчанию открывает экран **Сегодня** и сама выбирает турнир, который требует работы: активный, просроченный предстоящий, незакрытый после игры или ближайший будущий. Сверху показана цепочка **Заявки → Чек-ин → Рассадка → Игра → Результаты → Очки**, а большая кнопка всегда ведёт к следующему безопасному действию.

Типичный цикл:

1. Проверить заявки и при необходимости отправить напоминание.
2. Открыть быстрый чек-ин и нажать только на реально пришедших игроков.
3. Сформировать рассадку, проверить столы и опубликовать места.
4. Запустить турнир — регистрация закроется одновременно со сменой статуса.
5. В результатах одним нажатием загрузить пришедших. В режиме выбывания отмечать игроков в порядке выхода из игры.
6. Сохранить места, проверить суммы и начислить очки одним атомарным пакетом.

Черновик порядка мест, прогресса выбывания и сумм автоматически хранится в браузере до серверного сохранения результатов. Массового чек-ина намеренно нет: эта операция должна отражать реальное присутствие каждого человека.

## Рассадка игроков

В разделе **Рассадка** администратор выбирает турнир, количество мест за столом и при необходимости точное число столов. Сервер случайно и равномерно распределяет зарегистрированных игроков; разница в заполнении столов не превышает одного человека. Можно ограничить выбор только прошедшими чек-ин.

Игрока можно выбрать нажатием, затем перенести на свободное место или поменять местами с другим игроком. Любое ручное изменение снимает публикацию, чтобы игроки не видели устаревшие данные. После проверки администратор публикует рассадку: место появляется на главной странице Mini App, а бот отправляет каждому номер стола и места.

Seed случайной рассадки, генерация, перестановки, снятие с места, публикация и скрытие записываются в аудит. Завершённые и отменённые турниры защищены от изменения рассадки.

## Телефоны и оформление

В профиле игрок может добровольно нажать **Поделиться**. Telegram показывает системное окно подтверждения и отправляет боту только собственный контакт пользователя. Номер сохраняется после проверки Telegram ID, доступен только защищённым административным маршрутам и отображается в карточке игрока. Команда `/phone` предоставляет тот же сценарий через чат с ботом.

Фон рейтинговой карточки меняется в **Настройки → Оформление рейтинга**. Браузер обрезает изображение под формат карточки, уменьшает его и сохраняет в PostgreSQL, поэтому изменение не требует Vercel-деплоя. Поддерживаются PNG, JPEG и WebP.

## Локальный запуск

Нужны Node.js 20+ и Docker.

```bash
docker compose up -d
npm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте `http://localhost:5173`. В примере включён локальный демо-вход для Telegram ID `111111111`; он совпадает с демо-администратором из seed.

Перед production обязательно отключите демо-вход: не задавайте `ALLOW_DEV_AUTH` или установите `false`.

## Создание бота

1. Откройте `@BotFather` в Telegram.
2. Выполните `/newbot`, задайте имя и username.
3. Сохраните выданный токен — он понадобится только в переменной `TELEGRAM_BOT_TOKEN` на Render.
4. После деплоя отправьте боту `/start`. Кнопка Mini App появится в ответном сообщении.
5. При желании задайте постоянную кнопку меню через `/setmenubutton` в BotFather, указав Vercel URL.

Токен нельзя добавлять в Git или в файлы `.env.example`.

## Деплой API и БД на Render

1. Загрузите папку проекта в GitHub.
2. В Render выберите **New → Blueprint** и подключите репозиторий. Render прочитает корневой `render.yaml`.
3. При создании укажите секретные переменные:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather;
   - `MINI_APP_URL` — сначала можно указать будущий или временный HTTPS URL, после деплоя Vercel заменить на настоящий;
  - `ADMIN_TELEGRAM_IDS` — один или несколько числовых Telegram ID через запятую, например `123456789,987654321`.
4. `DATABASE_URL`, `JWT_SECRET` и `TELEGRAM_WEBHOOK_SECRET` создаются автоматически.
5. Дождитесь статуса **Live** и скопируйте URL вида `https://poker-club-api.onrender.com`.
6. Проверьте `https://ВАШ-API.onrender.com/health` — ответ должен содержать `"status":"ok"`.

Миграции БД запускаются автоматически при старте контейнера. Демо-seed на production не запускается, чтобы случайно не удалить реальные данные.

### Какие данные хранятся на Render

- Telegram ID, имя, username, роль и текущие очки пользователя;
- сезоны, турниры, места игроков и уведомления;
- заявки на турниры, очередь, шаблоны расписания и итоговые таблицы сезонов;
- столы, текущая рассадка, статус публикации и добровольно переданные номера телефонов;
- настраиваемое изображение рейтинговой карточки;
- журнал очков с суммой, причиной, автором изменения и балансом после операции;
- приватные заметки/теги и аудит административных действий.

Таблицы создаются Prisma-миграциями `202607190001_init`, `202607190002_manual_points_ledger`, `202607190003_browser_access`, `202607190004_club_operations` и `202607200001_seating_branding_contacts`. Миграции применяются автоматически и не удаляют существующих пользователей, очки, турниры или историю.

## Деплой интерфейса на Vercel

1. Создайте проект из того же GitHub-репозитория.
2. В **Root Directory** выберите `apps/web`.
3. Framework Preset: **Vite**. Остальные команды определятся автоматически.
4. Добавьте переменную окружения:
   - `VITE_API_URL=https://ВАШ-API.onrender.com/api`
5. Выполните Deploy и скопируйте HTTPS URL приложения.
6. Вернитесь на Render, замените `MINI_APP_URL` на Vercel URL и выполните redeploy API.

После смены любого значения `VITE_*` на Vercel нужен новый deploy, потому что Vite встраивает эти переменные во время сборки.

## Как назначить администратора

Числовой Telegram ID отображается прямо на странице **Профиль**. Добавьте ID в `ADMIN_TELEGRAM_IDS` на Render и выполните redeploy. При следующем открытии Mini App пользователь получит роль администратора и увидит кнопку со щитом.

Если ID несколько, перечислите их через запятую без пробелов или с пробелами — оба формата поддерживаются.

## Первичная настройка клуба

1. Зайдите в Mini App аккаунтом администратора.
2. Откройте кнопку со щитом или блок **Управление клубом** в профиле.
3. Создайте активный сезон.
4. Создайте ближайший турнир.
5. Игроки записываются сами; при необходимости управляйте списком во вкладке **Участники**.
6. Перед игрой откройте **Рассадка**, задайте размер столов, сформируйте и опубликуйте места.
7. После игры откройте **Турниры → Результаты**, расставьте игроков, сохраните места, проверьте суммы и нажмите **Начислить всем**.
8. Для индивидуальной корректировки откройте **Игроки → Баланс**. Ошибочную операцию можно отменить из истории.
9. В конце сезона нажмите **Настройки → Завершить** и подтвердите сохранение итоговой таблицы.

## Рабочее пространство администратора

- **Сегодня** — текущий турнир, этапы рабочего цикла, следующее действие, исключения, показатели клуба и быстрые действия.
- **Игроки** — расширенный поиск; очки, безопасная отмена, заметки, теги, результаты и персональный браузерный доступ.
- **Турниры** — параметры, регистрация, очередь, шаблоны, уведомления, результаты и пакетное начисление.
- **Рассадка** — автоматическое распределение, ручные перемещения, столы, публикация и Telegram-уведомления.
- **Аудит** — фильтруемый журнал действий с состоянием до и после изменения.
- **Доступ** — создание приглашений, поиск активных сессий и их отзыв.
- **Настройки** — сезоны и их финализация, оформление рейтинговой карточки, шаблоны причин и теги игроков.

На телефоне меню состоит из четырёх пунктов. Разделы **Рассадка**, **Аудит**, **Доступ** и **Настройки** находятся внутри **Ещё**.

Активация другого сезона сбрасывает текущие значения `User.points` до нуля, но не удаляет историю операций. Интерфейс требует отдельного подтверждения. Повторное редактирование уже активного сезона баланс не сбрасывает.

Пользователь появляется в БД после первого открытия Mini App. Чтобы бот мог отправить ему уведомление, пользователь должен хотя бы один раз нажать `/start`.

## Основные переменные окружения

| Переменная | Где | Назначение |
|---|---|---|
| `DATABASE_URL` | Render API | Подключение PostgreSQL |
| `JWT_SECRET` | Render API | Подпись сессии Mini App |
| `TELEGRAM_BOT_TOKEN` | Render API | Проверка Telegram-входа и работа бота |
| `TELEGRAM_WEBHOOK_SECRET` | Render API | Защита webhook бота |
| `MINI_APP_URL` | Render API | Vercel URL для CORS и кнопок бота |
| `ADMIN_TELEGRAM_IDS` | Render API | Белый список администраторов |
| `CLUB_TIMEZONE` | Render API | Часовой пояс уведомлений, по умолчанию `Europe/Moscow` |
| `VITE_API_URL` | Vercel | Публичный URL API с окончанием `/api` |

## Важные замечания

- Это система клубных очков, а не денежных ставок: платежей, кошельков и вывода средств в коде нет.
- API использует проверку Telegram-подписи, JWT, Helmet, CORS, ограничение частоты запросов и HTTP-сжатие.
- Render free-инстанс может засыпать при простое, поэтому первое открытие иногда занимает дольше обычного.
- Перед большим запуском рекомендуется перейти на постоянный тариф PostgreSQL и настроить резервные копии.
